# 美团 AI Agent 跨业务智能规划系统 - 设计方案

## 一、项目概述

### 1.1 核心问题
美团拥有外卖、到店餐饮、休闲娱乐、打车等多个独立业务，用户在规划复杂出行时需要在多个 App 间反复切换，体验割裂。

### 1.2 解决方案
构建一个 **任务导向型智能体（Task-Oriented Agent）**，通过自然语言理解用户需求，自动拆解任务、跨业务编排、智能执行，并具备异常自愈能力。

### 1.3 核心创新点

1. **多线程并发规划**：围绕核心人员（孩子、老婆）的并行需求进行规划
2. **三层异常处理机制**：Retry → Fallback → Replan，实现高容错弹性执行
3. **跨业务交叉销售**：到店综合 + 到店餐饮 + 即时零售的完美融合

## 三、核心场景设计

### 3.1 场景描述

> **用户（小明）**：这周六带老婆孩子出去玩，孩子5岁，老婆在减肥，要有惊喜

### 3.2 任务拆解

| 时间 | 任务 | 工具调用 | 约束条件 |
|------|------|----------|----------|
| 提前 | 查询天气 | Weather_API | 检测是否需要室内方案 |
| 14:00-16:30 | 儿童乐园 | Search_POI | 适合5岁、室内、评分>4.5 |
| 17:00-18:30 | 晚餐 | Search_POI + Book_Restaurant | 低卡、轻食、有宝宝椅 |
| 17:00 | 云排队 | Check_Queue | 提前取号减少等待 |
| 17:30 | 惊喜配送 | Order_Delivery | 鲜花/蛋糕定时送到餐厅 |

### 3.3 执行流程

```
Step 1: Intent Recognition
├── 人物: 老婆(减肥需求) + 孩子(5岁)
├── 需求: 娱乐 + 餐饮 + 惊喜
└── 约束: 低卡饮食 + 适龄活动

Step 2: Weather Check
├── Tool: Weather_API(date="周六")
├── 结果: 晴天 28°C
└── 决策: 户外/室内均可

Step 3: Entertainment Planning
├── Tool: Search_POI(category="儿童乐园", keywords=["适合5岁", "室内"])
├── 结果: 奇乐儿儿童主题乐园 (评分4.8, 距离120m)
└── 决策: 选定此地点

Step 4: Dining Planning
├── Tool: Search_POI(category="餐厅", keywords=["低卡", "轻食"])
├── 结果: 新元素餐厅 (评分4.7, 距离150m)
└── 决策: 选定此餐厅

Step 5: Restaurant Booking
├── Tool: Book_Restaurant(restaurant_id="rest_001", time="17:00", party_size=3)
├── 结果: 预订成功，预订号 BK202605141530
└── 备选: 若满座则切换到 wagas

Step 6: Queue Management
├── Tool: Check_Queue(restaurant_id="rest_001", action="take_number")
├── 结果: 排队号 A036，前面5桌
└── 决策: 到店前30分钟自动取号

Step 7: Surprise Arrangement
├── Tool: Order_Delivery(item_type="鲜花", deliver_to="新元素餐厅", deliver_time="17:30")
├── 结果: 订单号 DL202605141530，预计17:30送达
└── 通知: "鲜花将在您用餐时送达，给老婆一个惊喜！"
```

## 四、异常处理机制

### 4.1 三层异常处理架构

```
┌─────────────────────────────────────────────────────────────┐
│                    Exception Handler                        │
│                                                             │
│  Layer 1: RETRY (自动重试)                                  │
│  ├── 指数退避: 1s → 2s → 4s                                │
│  ├── 最大重试: 3次                                          │
│  └── 适用: 网络超时、API限流                                │
│                                                             │
│  Layer 2: FALLBACK (备选方案)                               │
│  ├── 自动切换到预设的备选方案                                │
│  ├── 保持相同目标，改变实现路径                              │
│  └── 适用: 餐厅满座、商品售罄                               │
│                                                             │
│  Layer 3: REPLAN (重新规划)                                 │
│  ├── 触发状态机回到 PLANNING 状态                           │
│  ├── 基于新信息重新生成计划                                  │
│  └── 适用: 天气突变、重大环境变化                           │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 异常场景演示

#### 场景 A：餐厅满座

```
触发条件: Book_Restaurant 返回 "seat_unavailable"

处理流程:
1. 捕获异常，错误级别 = FALLBACK
2. 查找任务的备选方案 (fallback_tool)
3. 自动切换到 wagas 餐厅
4. 重新执行预订
5. 向用户推送通知:
   "新元素餐厅已满座，已为您切换到 wagas（距离320m，评分4.5），
    同样提供低卡轻食选项。预订已确认！"

状态转换:
EXECUTING → ERROR → EXECUTING (使用备选方案)
```

#### 场景 B：天气突变

```
触发条件: Weather_API 返回 "阵雨"，outdoor_friendly = false

处理流程:
1. 检测到天气影响户外活动
2. 触发 REPLAN 级别处理
3. 状态机回到 PLANNING
4. 重新规划: 将户外活动替换为室内
5. 向用户推送通知:
   "检测到下午有阵雨，已将游乐场调整为室内区域，
    并更新了后续行程时间。"

状态转换:
EXECUTING → ERROR → PLANNING → EXECUTING
```

#### 场景 C：配送延迟

```
触发条件: Order_Delivery 返回 "预计延迟30分钟"

处理流程:
1. 计算新配送时间: 17:30 → 18:00
2. 检查是否影响主流程
3. 餐厅用餐时间 17:00-18:30，18:00仍在用餐 → 无需调整
4. 向用户推送通知:
   "鲜花配送预计延迟30分钟，将在18:00送达。
    届时您仍在用餐，不影响惊喜效果！"

状态转换:
EXECUTING → EXECUTING (无需状态变更)
```

## 七、技术实现要点

### 7.1 ReAct 架构实现

```python
# 核心循环
while not task_completed:
    # Reason: 推理当前状态
    current_state = analyze_situation()

    # Act: 执行下一步动作
    action = decide_action(current_state)
    result = execute_tool(action)

    # Observe: 观察结果
    if result.success:
        update_plan(result)
    else:
        handle_exception(result)
```

## 八、总结

本方案通过 **ReAct 架构 + 状态机管理 + 三层异常处理**，实现了：

1. **智能化**: 自然语言理解用户意图，自动拆解跨业务任务
2. **高容错**: Retry → Fallback → Replan 三层异常处理
3. **高价值**: 到店综合 + 到店餐饮 + 即时零售交叉销售
4. **可演示**: 三个完整场景覆盖正常、异常、重新规划

这不仅是一个技术 Demo，更是美团 AI 商业化的可行路径。
