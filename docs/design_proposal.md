# 美团 AI Agent 跨业务智能规划系统 - 设计方案

## 一、项目概述

### 1.1 核心问题
美团拥有外卖、到店餐饮、休闲娱乐、打车等多个独立业务，用户在规划复杂出行时需要在多个 App 间反复切换，体验割裂。

### 1.2 解决方案
构建一个 **任务导向型智能体（Task-Oriented Agent）**，通过自然语言理解用户需求，自动拆解任务、跨业务编排、智能执行，并具备异常自愈能力。

### 1.3 核心创新点

1. **双层规划架构**：路线规划引擎（算法）+ LLM 任务生成（AI），兼顾确定性和灵活性
2. **三层异常处理机制**：Retry → Fallback → Replan，实现高容错弹性执行
3. **剧本杀叙事引擎**：把普通 Citywalk 变成沉浸式剧情冒险
4. **跨业务交叉销售**：到店综合 + 到店餐饮 + 即时零售的完美融合

## 三、核心场景设计

### 3.1 场景描述

> **用户（小明）**：这周六带老婆孩子出去玩，孩子5岁，老婆在减肥，要有惊喜

### 3.2 任务拆解

| 时间 | 任务 | 工具调用 | 约束条件 |
|------|------|----------|----------|
| 提前 | 查询天气 | Weather_API | 检测是否需要室内方案 |
| 14:00-16:30 | 儿童乐园 | Search_POI | 适合5岁、室内、评分>4.5 |
| 17:00-18:30 | 晚餐 | Search_POI + Book_Restaurant | 低卡、轻食、有宝宝椅 |
| 17:00 | 云排队 | Check_Queue | 提前取号减少等待 |
| 17:30 | 惊喜配送 | Order_Delivery | 鲜花/蛋糕定时送到餐厅 |

### 3.3 执行流程

```
Step 1: Intent Recognition
├── 人物: 老婆(减肥需求) + 孩子(5岁)
├── 需求: 娱乐 + 餐饮 + 惊喜
├── 约束: 低卡饮食 + 适龄活动
└── 场景: FAMILY

Step 2: Route Planning
├── 候选 POI 筛选（16 品类 50+ 条数据）
├── 综合评分（评分 35% + 品类匹配 15% + 预算 20% + 多样性 15% + 个性化 15%）
├── 贪心构建初始路线
└── 2-opt 优化（带时间窗口校验）

Step 3: Task Generation (LLM / 规则)
├── T1: Weather_API → 天气检查
├── T2: Search_POI → 儿童乐园搜索
├── T3: Search_POI → 餐厅搜索
├── T4: Book_Restaurant → 餐厅预订
├── T5: Check_Queue → 排队取号
└── T6: Order_Delivery → 鲜花配送

Step 4: User Confirmation
└── 展示方案 → 等待用户确认

Step 5: Execution (按依赖顺序)
└── 逐个调用工具 → 异常处理 → 结果汇总
```

## 四、异常处理机制

### 4.1 三层异常处理架构

```
┌─────────────────────────────────────────────────────────────┐
│                    Exception Handler                        │
│                                                             │
│  Layer 1: RETRY (自动重试)                                  │
│  ├── 指数退避: 1s → 2s → 4s                                │
│  ├── 最大重试: 3次                                          │
│  └── 适用: 网络超时、API限流                                │
│                                                             │
│  Layer 2: FALLBACK (备选方案)                               │
│  ├── 自动切换到预设的备选方案                                │
│  ├── 保持相同目标，改变实现路径                              │
│  └── 适用: 餐厅满座、商品售罄                               │
│                                                             │
│  Layer 3: REPLAN (重新规划)                                 │
│  ├── 触发状态机回到 PLANNING 状态                           │
│  ├── 基于新信息重新生成计划                                  │
│  └── 适用: 天气突变、重大环境变化                           │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 异常场景演示

#### 场景 A：餐厅满座

```
触发条件: Book_Restaurant 返回 "seat_unavailable"

处理流程:
1. 捕获异常，错误级别 = FALLBACK
2. 查找任务的备选方案 (fallback_tool)
3. 自动切换到备选餐厅
4. 重新执行预订
5. 向用户推送通知

状态转换: EXECUTING → ERROR → EXECUTING (使用备选方案)
```

#### 场景 B：天气突变

```
触发条件: Weather_API 返回 "阵雨"

处理流程:
1. 检测到天气影响户外活动
2. 触发 REPLAN 级别处理
3. 状态机回到 PLANNING
4. 重新规划: 将户外活动替换为室内
5. 向用户推送通知

状态转换: EXECUTING → ERROR → PLANNING → EXECUTING
```

## 五、剧本杀叙事引擎

### 5.1 设计理念

不只是推荐去哪玩，而是把整座城市变成沉浸式游戏场，Agent 做你的 DM（主持人）。

### 5.2 触发机制

- 关键词检测：剧情、故事、剧本、悬疑、冒险、挑战、推理、解谜、citywalk、沉浸
- 仅在用户输入包含相关词汇时激活，避免干扰普通规划

### 5.3 故事模板

| 模板 | 适用场景 | Checkpoint 数 |
|------|----------|---------------|
| 家庭冒险 | FAMILY / PARENT_CHILD | 4-6 |
| 浪漫约会 | DATE | 4-5 |
| 朋友探险 | FRIENDS | 5-6 |
| 团队挑战 | TEAM_BUILDING | 5-6 |

### 5.4 Checkpoint 映射

故事的 Checkpoint 动态映射到路线节点，路线节点多/少于模板时自动适配。

## 六、商业价值分析

### 6.1 交叉销售机会

| 业务组合 | 场景 | 额外收入 |
|----------|------|----------|
| 到店综合 + 到店餐饮 | 游乐场 + 餐厅 | 餐饮订单 |
| 到店餐饮 + 即时零售 | 餐厅 + 鲜花配送 | 闪购订单 |
| 到店综合 + 打车 | 商场 + 打车往返 | 出行订单 |

### 6.2 用户体验提升

- **规划效率**: 从 30+ 分钟手动规划 → 1 分钟自然语言描述
- **决策质量**: AI 基于大数据推荐最优组合
- **惊喜体验**: 自动安排鲜花/蛋糕定时配送
- **沉浸感**: 剧本杀叙事让普通出行变成冒险

## 八、总结

本方案通过 **双层规划 + 状态机管理 + 三层异常处理 + 剧本杀叙事引擎**，实现了：

1. **智能化**: 自然语言理解用户意图，自动拆解跨业务任务
2. **高容错**: Retry → Fallback → Replan 三层异常处理
3. **高价值**: 到店综合 + 到店餐饮 + 即时零售交叉销售
4. **沉浸感**: 剧本杀叙事让普通出行变成冒险
5. **可演示**: 多个完整场景覆盖正常、异常、剧情模式

这不仅是一个技术 Demo，更是美团 AI 商业化的可行路径。
